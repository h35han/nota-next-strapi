# NŌTA — frontend

Next.js 16 (App Router) front end for the NŌTA smart-pen site, rebuilt as a
faithful port of <https://nota.uprock.pro/> — a Taptop-generated scrollytelling
page — with content served from the Strapi backend in `../backend`.

## Running

From the repo root:

```bash
npm run dev           # Strapi + Next together
npm run dev:frontend  # Next only (expects Strapi on :1337)
```

`npm run env:setup` copies `.env.example` → `.env.local` on first install.

## How this port is put together

The original is a Taptop "mosaic" page: a declarative design system plus a
declarative animation spec. Rather than reinterpreting it, this app vendors both
and replays them.

```
app/styles/reference/     the reference's four stylesheets, verbatim
  base.css                Taptop base reset (.section/.div/.text/.container…)
  design.css              per-element rules emitted by the Taptop constructor
  shared.css              the design's own classes (typography, colours, sections)
  animations.css          the "before" states of animated elements
app/styles/app.css        html/body, Lenis, scramble-text + hero-Lottie helpers
lib/taptop/spec.json      the whole animation spec (element → animation, per breakpoint)
lib/taptop/engine.ts      the Taptop animation runtime (ScrollTrigger + GSAP keyframes)
lib/scramble.ts           the scramble-text intro
lib/smooth.ts             Lenis, scroll locking, anchor navigation
```

`lib/taptop/spec.json` is generated by `scripts/gen-taptop-spec.py` from the
captured page (`.reference/scripts/inline_13.js`). Re-run it after re-capturing
the reference. It resolves Taptop's breakpoint inheritance ahead of time, so the
runtime is a plain lookup.

Two rules in that generator are easy to get wrong and both cause visible bugs:

1. **Inheritance is `mergeWith` with a `null`-keeps-existing customiser**, and
   keyframe arrays merge *index-wise*. A `(min-width: 1440px)` layer can
   therefore override only `keyframes[1].y` and inherit `x`/`z`.
2. **Hold keyframes are load-bearing.** An effect whose two keyframes are
   identical (`y: 140% → 140%` over keyframes 0→25) is not a no-op — it parks
   the element below the fold before the reveal and supplies the `from` value
   the next effect animates away from. Filtering those out as "constant" makes
   the specs cards start in place and visibly drop before rising.

**The stylesheets are imported in the reference's own `<link>` order**
(`base → design → shared → animations`). `design.css` and `shared.css` have
equal specificity, so that order is load-bearing — swapping them silently
changes element sizes (the colour slider, for instance, collapses from 350vh to
710px).

### The animation engine

Every animated element in the reference carries an id of the form
`<9 chars>_<n>`. `lib/taptop/spec.json` maps those ids to animation
definitions, and `lib/taptop/engine.ts` turns each one into the same GSAP
timeline the reference builds:

* `SCROLL_TRANSFORM` → `gsap.timeline({ scrollTrigger }).to(el, { keyframes })`
  with `start: "<startPosition>+=<startOffset> <scrollerStartOffset>"`,
  `end: "<endPosition>+=<endOffset> <scrollerEndOffset>"` and
  `scrub: <smoothing>`. Keyframe positions are percentages of the trigger's
  scroll range.
* `APPEAR_ON_SCREEN` → a `fromTo` fired at `<stageOfAppear> bottom`.

**Therefore: keep the `id` attributes when editing section markup** — they are
the wiring. Same for the class names; the vendored CSS styles them by exact
name.

Breakpoint inheritance follows Taptop's ladder
(`(min-width:1920px) → 1440 → 1280 → screen → (max-width:991px) → 767 → 479`,
base `screen`) and is resolved at build time into a sparse per-breakpoint
`sel` array — a `null` slot means "identical to the base slot". The effect
list is never merged by name: a single animation chains several effects of the
same kind (three `MOVE`s staging a card's fall, hold and rise).

### Page composition

`app/page.tsx` owns the wrapper tree. It is not decorative: the desktop page is
a scrollytelling "camera" built from `position: sticky` sections whose offsets
are bounded by their wrappers. Getting a wrapper wrong shifts every sticky
offset after it, so keep the nesting in sync with
`.reference/sections/_full_body.html`.

```
.black-bg__wrapper
  section.cover                 270vh, sticky top -170vh
  section.transition-specs      180vh, sticky top 0, margin-top -100vh
  .sticky__wrapper
    section.specs               300vh, sticky top -200vh, margin-top -100vh
    section.who-transition      180vh, margin-top -70vh
  section.who                   sticky top -300vh, margin-top -100vh
  .sticky-wrapper
    section.paper               600vh, sticky top 0
    section.inside__transition  230vh, margin-top -100vh
section.inside
section.details
…the `--static` halves below 992px…
.scroll-wrapper
  section.section-colors        350vh
  footer.footer
```

Both the desktop sections and their `--static` (< 992px) counterparts are
rendered; the vendored CSS toggles them at the 991px breakpoint.

### The hero

`app/sections/Cover.tsx` + `app/components/CoverLottie.tsx`. The reference plays
a **Lottie** document and seeks it frame by frame from the scroll position, so
that is what we do: `lottie-web` is mounted with `autoplay:false, loop:false`
and `goToAndStop(frame, true)` runs on every scroll tick. The frame comes from
the first ancestor taller than the viewport — `.cover__camera` is
`position:sticky`, so that ancestor is `.black-bg__wrapper`, exactly as in the
reference. Fallbacks in order: Lottie JSON → all-keyframe MP4 → still image.

The Lottie file is Strapi-bound: `product.cover_lottie` (a `files` media field
on the Product content type). The headline uses the reference's scramble-text
intro.
